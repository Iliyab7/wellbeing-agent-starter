# Run Wellbeing in Dot

When the participant shares this package for Wellbeing, perform the following work in the current turn. On every return, start from the same private Sheet. Use the participant’s language. These steps work with host tools and conversational roles.

1. **Recover the goal and the team's place to work.** Use the current request, authorized conversation and the participant's designated private Wellbeing Sheet. Follow its saved link or stable spreadsheet ID. If already authorized to locate it, look in the designated folder and inspect its existing layout. If several files could belong to the participant, ask which one. Recover their current goal, permitted sources, feedback, last finding and unfinished work. Reuse valid choices. If the goal is still unknown, ask the one question that decides what help matters today.
2. **Look for evidence that can change today's answer.** The Manager assigns the relevant work. If Dot lacks worker tools, carry out the responsibilities within this chat. The Analyst opens a small, relevant sample from sources already authorized for this goal: an existing export, a prior self-report, or the relevant calendar window, for example. Record source, date/window, unit and gaps. Read existing SyncFit or other exports with the available file tools when the format and units can be verified; keep overlapping periods separate. If a source is empty or unavailable, continue with another authorized source. A planned meeting provides context for the day; measured sleep and reported energy need their own evidence. If all useful evidence is missing, explain the gap and ask one targeted question that lets the team help now.
3. **Prepare the health section of the personal newspaper.** The Manager owns a short section ready for the Chief of Staff to use as written. Give it a date and a meaningful headline. In a few lines say what was observed, when and from which source, why it matters to the chosen goal today, and one feasible option if warranted. Include uncertainty that changes the interpretation. The Coach helps with a practical option when useful. Honor earlier feedback. On the first run show the useful result in this conversation. If the participant has selected a newspaper, use its agreed format, deadline and destination. Without authority to publish, show the ready section privately. If evidence supports no useful item, give the limited answer and smallest useful next step; let the Chief defer the item. A scheduled issue or a message to another channel requires its own existing authority.
4. **Save and check continuity.** The Manager uses the host's actual Google Sheets read/write tools within the agreed scope. Reuse the participant's existing structure. If no Sheet exists, create a private one only in an authorized destination and scope. Record the goal, evidence reference and date, finding, section or delivery status, and next owner/action or closure. Keep participant feedback and corrections linked to the original item. When feedback or a source correction changes a finding, update its linked section and carry the correction forward. Re-read the updated cells; on retry or an uncertain write, find the original item before adding another. Keep the Sheet link/ID in the agreed private continuation location. In another chat reopen that same Sheet, retrieve the latest state, and give only the relevant update. Reuse the previous item if its evidence has not changed. If read or write is unavailable, deliver the useful result in chat and say exactly which memory step failed. If needed, ask for the existing Sheet link privately.
5. **Return the result.** Lead with the health section or useful answer. Add at most one brief operational note when it affects the person, such as an unsaved correction or a pending decision. Keep technical receipts in private memory. For an agreed recurring issue, reuse and verify its existing job, then distinguish saved settings, observed execution and actual delivery.

Optional: consult [role instructions](agents/registry.json) when a task needs them. For new phone data use [phone setup](PHONE-SETUP.md) on request. [Private processing](docs/mvp/inbox-runtime.md) and [hosted HTTP](INSTALL-HTTP.md) are separate technical options.
