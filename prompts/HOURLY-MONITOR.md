# Private monitoring job

Each invocation resolves current GitHub main for Iliyab7/wellbeing-agent-starter and opens INSTALL.md, CHAT-STARTER.md, agents/registry.json and the relevant Analyst and Manager instructions at that commit. Recheck current recurring grants and stop flags. Run the following for each granted source, using its own saved coverage window.

Before listing, apply the standing authority and filter repair in INSTALL.md. Compare participant decision provenance against the effective query and job payload. Self-heal stale filters, replay uncovered and previously pending observations and verify actual Sheet rows. A previous run's query or a note written by Dot is not a grant or a user restriction. Honor explicit limits and stops.

1. Enumerate the complete change feed or paginate the authorized window with overlap. In Gmail list message IDs by time and participant-granted account/mailbox boundaries only; fetch individual messages including plain text, HTML and attachment metadata as needed. When using Gmail search, the time portion can be expressed as after:<overlapping-start-epoch> before:<end-epoch>. A known subject, a particular sender, a filename, or has:attachment belongs only in an optional downstream parser unless the participant explicitly limited the grant. Never use parser matches as the candidate list. Apply the same listing-before-classification rule to other sources.
2. Triage each candidate within its grant. Device arrival/departure notices without attachments can carry a timestamp and direction. Record those only when relevant and in scope; without a place label, leave place and activity unknown. Omit unrelated content. Do not require a sender-specific grant inside existing scope.
3. Reconcile all listed IDs as reviewed, outside scope or durably pending. Keep incomplete pages and failures for retry. Update the same private Sheet, verify writes and advance the per-source broad checkpoint only after reconciliation. Follow INSTALL.md for coverage, recovery and editorial decisions. Hourly checks are private; newspaper delivery retains its own schedule.

Apply [partial reports and open-item handling](../INSTALL.md#partial-reports-open-items-and-editorial-readback) during triage: read back each unresolved item's owner and next trigger before advancing discovery; work triggered items without repeating the entire old window. Verify the separate editorial disposition only when a review is due.
