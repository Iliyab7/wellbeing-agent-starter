# Wellbeing Agent Starter

**تکمیل طراحی ۸ نوامبر:** [حافظهٔ مشترک و ورودی خودکار](docs/shared-memory/README.md) در نقش‌ها و مسیر شروع ادغام شده است. مدیر ساختار Google Sheets را متناسب با فرد طراحی و اداره می‌کند؛ همهٔ اعضا مسئول ثبت کار و تبادل خود هستند. این نسخه دستور کار و معیار پذیرش را اضافه می‌کند؛ اتصال ابری یا شورتکات فعال ایجاد نمی‌کند.

**بستهٔ شروع آزمایش ول‌بینگ شخصی با دات یا دستیار دلخواه — نسخهٔ ۰٫۱٫۰**

این بسته به دستیار شما نقش «چیف‌آف‌استاف» می‌دهد: ابتدا هدف، ترجیحات و حدود اختیار شما را روشن می‌کند، سپس تیم ول‌بینگ را با سه مسئولیت **مدیر، تحلیلگر وضعیت و روندها، و مربی اهداف و عادت‌ها** راه می‌اندازد و اداره می‌کند. دات در این نسخه جای نقش الهام را می‌گیرد؛ هاروی نام تیم توسعه است.

هدف، همراهی متناسب با زندگی شماست. شروع می‌تواند فقط یک پرسش یا یک عادت انتخابی باشد. داشتن ساعت هوشمند، اتصال Apple Health یا گزارش روزانه شرط شروع نیست.

## از کجا شروع کنم؟

### ۱. برای تست با دات یا بات خودت

[START-HERE.md](START-HERE.md) را باز کن. اگر دستیار می‌تواند فایل‌های گیت‌هاب را بخواند، این متن را به آن بده:

> بستهٔ https://github.com/Iliyab7/wellbeing-agent-starter را بخوان و از START-HERE.md شروع کن. نقش چیف‌آف‌استاف ول‌بینگ من را بگیر. امکانات واقعی خودت را بررسی کن، راهنمای CHAT-STARTER.md را اجرا کن و تیم را با نقش‌های مدیر، تحلیلگر و مربی راه بینداز. از شناخت مجاز فعلی من استفاده کن و فقط تصمیم‌های لازم دربارهٔ هدف، داده، اختیار و شیوهٔ تماس را از من بپرس. سپس اولین کمک مفید را ارائه کن. اگر ساخت ایجنت مستقل یا زمان‌بندی در این محیط ممکن نیست، روشن بگو و از مسیر نقش‌های مجازی و گفت‌وگوی فعلی شروع کن.

اگر دستیار به گیت‌هاب دسترسی ندارد، فایل [CHAT-STARTER.md](CHAT-STARTER.md) را دانلود و همان‌جا پیوست کن. این فایل مسیر شروع را در خود دارد. راهنمای انسانی در [راهنمای تست فارسی](docs/participant-pilot-fa.md) است.

### ۲. برای تست فنی روی کامپیوتر

Python 3.11 یا جدیدتر لازم است. بسته را دانلود و از پوشهٔ آن اجرا کن؛ مسیر اصلی به هیچ کلید API یا نصب کتابخانهٔ خارجی نیاز ندارد:

```sh
python scripts/demo.py
python -m unittest discover -s tests -v
python scripts/validate_package.py
```

دمو با دادهٔ **ساختگی** کار می‌کند. برای شروع پروندهٔ خصوصی و فرمان‌های دقیق، [راهنمای اجرا](docs/runtime.md) را ببین. دادهٔ شخصی را داخل پوشهٔ پروژه یا GitHub نگه ندار.

### ۳. برای تیم هاروی / توسعه

از [بستهٔ تحویل توسعه](docs/harvey-handoff.md) شروع کن: معماری، قراردادها، تصمیم‌های فعلی، مرزهای پیاده‌سازی و معیارهای پذیرش در آن مشخص شده‌اند. [تحلیل منابع](docs/source-analysis.md) و [تطبیق نیازمندی‌ها](docs/requirements-traceability.md) نشان می‌دهند هر بخش از کجا آمده و چه تصمیمی مخصوص این آزمایش است.

## مرز این نسخه

این یک **بستهٔ آمادهٔ آزمایش اولیه** است. هوش گفت‌وگو و اجرای ابزارهای بیرونی را محیط میزبان فراهم می‌کند؛ کد پایتون، اجرای مرجع محلی و قابل آزمون است. بارگیری فایل به‌تنهایی اتصال ساعت، نصب ایجنت مستقل، اعلان پس‌زمینه یا حافظهٔ دائمی ایجاد نمی‌کند. دستورالعمل‌ها جداسازی امنیتی فنی ایجاد نمی‌کنند؛ ابزارهای میزبان و رضایت شخص باید واقعاً بررسی شوند.

دات باید مشخصات هر عضو، مهارت‌های تخصیص‌یافته، حدود دسترسی، تسک‌های باز و گزارش‌های دریافتی را نگه دارد. داشتن فایل نقش با ساخته‌شدن ایجنت یکی نیست؛ گرفتن گزارش هم با تأیید کیفیت و بسته‌شدن تسک یکی نیست. این مراحل در [نقشهٔ عملیاتی تیم](agents/team-blueprint.json) و راهنمای ادارهٔ تیم تعریف شده‌اند.

حوزهٔ کمک غیرپزشکی است. تشخیص، تغییر درمان یا دارو و تصمیم اضطراری خودکار در این بسته نیست. برای رضایت، حذف و نگهداری، [حریم خصوصی و حدود خدمت](docs/privacy-and-safety.md) را بخوان.

آزمون واقعی روی حساب دات/بات و پذیرش صاحب مسئله باید در پایلوت ثبت شود. موفقیت تست‌های کد به معنی اثبات اثر روی سلامت یا برتری تیم سه‌نفره نیست.
